# CarLife 测试音视频与安卓车机端验收

日期：2026-10-21。应用构建：[f4e4045 / Actions 39628785953](https://github.com/Aki894/CarLink/actions/runs/39628785953)，测试、ARMv7 编译及产物上传成功。本轮没有修改固件或构建流程。

## 实现

- 显式 `--test-media DIR` 才启用合成媒体；默认仍为协议开发模式。
- 2 秒 H.264 baseline 循环，1280×720、30 fps、无 B 帧；按 AUD 分帧，启动及恢复发送 SPS/PPS+IDR。
- PCM16LE、44100 Hz、双声道，20 ms 一包；低音量 440 Hz 间歇提示音。
- 有界媒体队列，视频/音频分别用代际标记丢弃失效数据；暂停、重置、静音、降帧及暂停保活。
- 兼容 Java HU 不带结尾 NUL 的 AOA 字符串；USB 描述符按 IN、OUT 排列，适配 SDK 按固定索引选端点的行为。
- 4.1 基础握手；CarLife 2.0 摘要校验使用实际发送的 MD_INFO 和车机 nonce，无私钥或配对数据。
- 设备信息只发一次，避免双方重复握手。独立的 USB 对端接受通知在元信息及摘要响应后发送；显式拒绝会终止连接。有些 HU 直接进入视频初始化，有些另行返回接受结果，日志分别记录。
- HU 请求的显示尺寸作为偏好；INIT_DONE 如实返回资产中经 SPS 校验的实际编码尺寸。
