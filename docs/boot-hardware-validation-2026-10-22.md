## 首次转发联调

华为手机无线 ADB 与 CarLife 车机端可用。Type-C 通过手机 OTG 连接；手机在初始身份与 AOA 附件身份之间切换时出现 USB 应用选择和访问授权，需要选择车机端并确认。授权后实际完成 CarLife 4.1 握手、认证、USB 音频能力协商、800×480@30 视频协商和播放请求。用户确认看到了转发画面。

初版随后在 `0x68001`、11 字节触控消息处报 `invalid touch field` 并退出。修复为兼容 Protobuf 扩展字段与单值字段覆盖；格式错误或越界触控仅忽略当前事件，保留投屏会话。回归检查覆盖扩展字段、截断输入和异常触控后的命令处理。修复后的构建与实测结果在后续记录补充。

## 修复版复测

应用提交 `520b235ff8bfa03e53ed8e307be4db8885383a97`，已通过 [应用构建 39728191942](https://github.com/Aki894/CarLink/actions/runs/39728191942)，包含 Rust 回归、ARM 交叉编译、接收端测试、QEMU 音频和合成转发闭环。

本轮硬件联调另修复了两项问题：

- 音频初始化后追加模块状态通知，形成多个连续外层帧。TCP 接受该字节流，USB 写入校验原先只接受一个帧；现在先验证整批数据，再按每帧独立的头部和正文写入 USB。
- 解码器集中输出 PCM，USB 队列拥塞又触发全局媒体重置，导致手机反复创建音频对象，最终报 AudioTrack 创建失败。现在 PCM 按 20 ms 样本时钟发送，视频恢复保留音频状态，音频拥塞丢弃当前块，不反复重建音轨。

修复版已通过有线 SSH 安装到现有 SD 卡，保留启动配置和认证数据。用户先确认画面可正常点击，再确认“正常出声”；Android 日志显示 44100 Hz、双声道、16 bit 的 AudioTrack 成功启动。iPhone → 无线 CarPlay → H3 → USB CarLife → 安卓车机端的画面、媒体声音、触控返回已实测通过。

持续播放阶段同一 AudioTrack 从 13:34:38 运行至 13:35:24，停止日志记录累计交付 1,890,126 个音频帧，未再发生先前每约 0.38 秒重建播放对象的问题。此后数分钟服务保持运行，系统无失败单元；个别越界触控按设计丢弃当前事件，连接继续保持。

[完整 firmware job 39728628096](https://github.com/Aki894/CarLink/actions/runs/39728628096) 已成功完成镜像构建、完整内容校验、压缩校验和产物上传，应用来源与板上版本一致。镜像 artifact 为 `carlink-h3-refreshed-image`（ID `12403204903`）。
